An Android app that runs the open-source [ByeDPI](https://github.com/hufrea/byedpi) engine locally on your phone and sends your device's traffic through it using Android's `VpnService`. Its purpose is to help connections get past DPI (Deep Packet Inspection) filters that interfere with them.

## What it is, and what it is not

| ByeDPI for Android **is** | ByeDPI for Android **is not** |
| --- | --- |
| A local helper that changes how your connections are started, so some DPI filters misread them | A privacy tool: it does **not** encrypt traffic and does **not** hide your IP address |
| A real wrapper around the upstream ByeDPI engine | A fake or simulated connection: the status turns green only after every part is verified |
| Free, open source, no accounts, no analytics | A guarantee: results depend on your network and the strategy you choose |

ByeDPI also does **not** bypass DNS blocking or DNS poisoning. It only affects how connections are made after a name is resolved.

## How it works

```text
 Apps on your phone
        │  (all IPv4 traffic, optional IPv6)
        ▼
 Android VPN interface (TUN)        ← created by VpnService
        │
        ▼
 hev-socks5-tunnel (tun2socks)      ← turns packets into SOCKS5 requests
        │
        ▼
 ByeDPI proxy  127.0.0.1:1080       ← upstream engine applies the desync strategy
        │
        ▼
 Internet
```

- The ByeDPI engine is compiled from the upstream C sources with the Android NDK and bundled as `libbyedpi.so`.
- A small JNI layer starts the unmodified upstream `main()` in a **forked child process** and stops it with `SIGTERM`/`SIGKILL`. A fresh process per start means no leftover state, and an engine crash cannot take the app down.
- This app is excluded from its own VPN, so the proxy's outgoing connections do not loop back into the tunnel.
- **"Connected" is only shown when**: (1) the proxy answered a real SOCKS5 handshake, (2) Android created the VPN interface, and (3) the tunnel reports that it is running. The service re-checks the proxy and tunnel every second.

## Features

- Dark interface (black/charcoal, green accent) with one prominent Connect/Disconnect button
- Accurate status: Disconnected, Connecting, Connected, Disconnecting, or the exact error
- Session details: proxy and tunnel state, bytes sent/received, uptime, active strategy
- Settings for the supported engine options, with a live command preview
- Diagnostics screen: engine versions, state, an in-memory log, and a connectivity check that performs a real TLS handshake through the proxy
- Foreground notification with a Disconnect action

## Download and install

You do not need a PC or Android Studio. Everything is built by GitHub Actions.

1. Open the **Actions** tab of this repository and tap the latest run with a green check mark.
2. Scroll to **Artifacts** and download **ByeDPI-debug-apk** (a `.zip` file).
3. Extract the zip on your phone and open `app-debug.apk`. Android will ask you to allow installing apps from this source.
4. Open **ByeDPI**, tap **Connect**, and accept the Android VPN prompt.

Notes:

- The APK is a **debug build**. GitHub creates a new debug signing key on every run, so Android may refuse to update over an older build. Uninstall the old version first.
- Minimum Android version: 8.0 (API 26). Supported CPU types: `arm64-v8a`, `armeabi-v7a`, `x86_64`.
- If a run is red, open it and read the **Summary** section: it lists the error lines and the end of the build log.

## Settings

| Setting | Default | Meaning |
| --- | --- | --- |
| Local proxy port | `1080` | Port the proxy listens on, on `127.0.0.1` only (1024–65535) |
| DNS server for the VPN | `8.8.8.8` | IPv4 or IPv6 address. DNS queries are sent here through the tunnel |
| Proxy UDP traffic | on | Turning it off also stops UDP DNS, so names may stop resolving |
| Tunnel IPv6 traffic | off | Adds an IPv6 address and route to the VPN. Required for an IPv6 DNS server |
| Desync method | Disorder | None, Split, Disorder, Fake, OOB, or Disorder + OOB |
| Position | `1` | Where in the first request the method applies, for example `1`, `3+s`, `-1` |
| Fake packet TTL | `8` | Used only with the Fake method |
| TLS record split position | empty | Optional `--tlsrec` position, for example `1+s` |
| Apply only when blocking is detected | off | Uses `--auto=torst` with the timeout below |
| Detection timeout | `3` s | Used with blocking detection |
| Custom arguments | off | Replaces the options above with your own ByeDPI arguments |

The position format is `offset[:repeats:skip][+flags]`. A flag such as `+s` makes the offset relative to the TLS SNI. See the [upstream README](https://github.com/hufrea/byedpi/blob/main/README.md) for the exact meaning of every option.

**There is no universal strategy.** What works depends on your ISP and network. If one strategy does not work, try another method or position.

Custom arguments may not contain `-i/--ip`, `-p/--port`, `-D/--daemon`, `-w/--pidfile`, `-E/--transparent`, `-y/--cache-dump`, `-h/--help` or `-v/--version`. The app sets the listen address and port itself.

## Privacy

- No analytics, no ads, no accounts, no crash reporting.
- The app contacts nothing on its own. The only connection it starts is the optional check in **Diagnostics**, which goes through the local proxy to the host you type in.
- The log lives **in memory only** (last 300 entries) and is gone when the app process ends. It records app events such as "Proxy answered a SOCKS5 handshake". It never records visited sites, IP addresses or packet contents.
- The upstream engine's console output is discarded.

Permissions requested:

| Permission | Why |
| --- | --- |
| `INTERNET`, `ACCESS_NETWORK_STATE` | Local proxy and tunnel sockets, and the connectivity check |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_SPECIAL_USE` | Keeps the VPN alive while the app is closed |
| `POST_NOTIFICATIONS` | Shows the status notification (Android 13+) |
| VPN permission (system dialog) | Required by Android to create the VPN interface |

Known limitations:

- Some upstream options are not exposed in the UI (for example `--md5sig`, host lists and protocol filters). Use **Custom arguments** for options the UI does not cover. Some options depend on kernel support and may not work on every device.
- The engine runs as a child process of the app. If Android kills the app, the engine stops with it.
- Always-on VPN or another active VPN can prevent the interface from being created.

## Troubleshooting

| Message or symptom | What to try |
| --- | --- |
| *The native ByeDPI engine could not be loaded* | Your CPU type is not supported, or the APK is incomplete. Reinstall from the latest successful build |
| *The ByeDPI engine failed to start (code N)* | Check Custom arguments, and make sure the port is not used by another app. Open Diagnostics and copy the log |
| *The ByeDPI proxy did not start listening* | Change the port in Settings |
| *Android refused to create the VPN interface* | Turn off other VPN apps and "Always-on VPN", then try again |
| Connected, but nothing loads | Try another desync method or position, check the DNS address, and keep **Proxy UDP traffic** on |
| Some sites work, others do not | Normal: str
